# minty-quail — Tuning's fairness checks fail the suite; the field maths leaves Tuning (tuning A) · 2026-11-01


minty-quail's `tuning.md`, its first half: the checks that only logged, and the logic that lived beside
the balance numbers. The other half, the constants used by one owner, is still the item.

**Built.**
- `Tuning._ready()` is gone, and with it `validate_traffic`, `validate_signals` and
  `validate_return_patrols`, which pushed an error and returned false, so an unfair number shipped with a
  console line. The three contracts are the checks of `tests/test_tuning_fairness.gd`, the suite's own
  `t.check`s with the numbers in each message; they are not callable code, because nothing but a test
  called them. The horn, the horn sight, the door fractions, the walker's side-step, the side street's green
  and the return patrols' shape each fail the suite, so CI. `required_horn_time()` and `required_horn_sight()`
  stay on `Tuning`: the lethal vehicles' suites measure against them. The suites that asserted the same
  return-patrol shape (`test_return_patrols.gd`) and called the validators (`test_crowd.gd`,
  `test_blackout.gd`) dropped those lines. Shown to fail: `CAR_HORN_TIME` set to 0.5 failed the suite with
  "Unfair traffic: CAR_HORN_TIME 0.50s < required 1.39s (carriageway 64px)"; the value was restored.
- `Tuning.validate_pursuit()` stays where `EventDef.validate()` calls it: it is a row's own contract, run
  when the catalogue loads, and it fails the suites that load the catalogue.
- The layer exceptions that existed for the validators are gone: `Tuning` no longer names `CrowdAgent` or
  `CrowdLanes`.
- `falloff`, `field_eccentricity` and `field_scale` are `Field.falloff`, `Field.eccentricity` and
  `Field.scale` (`src/field.gd`, a static class in the data layer).
- `offscreen_boundary`, `min_offscreen_boundary`, `offscreen_lead` and `min_offscreen_lead` are
  `Offscreen.boundary`, `Offscreen.min_boundary`, `Offscreen.lead` and `Offscreen.min_lead`
  (`src/offscreen.gd`): not field maths, and the lead is the boundary plus a margin, so the four go together.
  `VIEW_HALF_EXTENT` and `OFFSCREEN_NOTICE` stay on `Tuning`.
- `pursuit_standoff` is `PursuitSpec.standoff`: it is the pursuit contract in distance, beside the spec the
  contract is stated over. `braking_distance` is `CarStrategy.braking_distance`: it is the car's.
- Nothing changed value; every caller, doc and comment names the new homes.
