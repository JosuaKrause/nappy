## Guarded retirement and owned scratch cleanup

The implementation incorporates the three storage-safeguard checkpoints into PR #461,
alongside silver-ibis's relevant-evidence rules and archive reduction. The user requests
incorporation after the audit distinguishes agent completion from delivery into the PR.

`tools/prune-merged.sh --all` inventories eligible merged branches without mutation;
`--all --apply` explicitly applies the same safety checks again. A local tip may equal
or be an ancestor of the merged PR head: ancestry proves stale local work is preserved
by that PR, whereas requiring exact equality unnecessarily retains old clean checkouts.
An open PR, unavailable merged commit, different remote head, unmerged local work,
dirty/untracked files, ignored files outside the regenerable caches, a lock or unreleased
agent ownership prevents retirement. The ignored-file check came from review: `git status` never
lists ignored paths, and the non-forced `git worktree remove` deleted an ignored `build/rec.mp4`
in a reproduction, so a recording, an uncopied capture or a worktree-local `.env` would have gone
without a word. The script names its regenerable list in one place (Godot's import cache, the
Python environment and its caches, Finder metadata, baked atlases, Web-template compiler scratch
and `build/.gdignore`); a compiled `build/web-template/` or an export under `build/web/` is
refused too, since what a person keeps there is theirs to delete. The main checkout and caller's worktree are protected. Brief headers release ownership
with `cleanup: ready` only after processes stop and useful artifacts are retained.
Mutation rechecks state, deletes the remote with an expected-head lease, removes the
worktree without force, and compare-deletes the local branch against its expected tip.

Successful Web-template builds retain the verified template and remove their compiler
and download scratch under an exclusive build lock. Failed builds retain diagnostics
and report their scratch path. The PR updater removes its own clean scratch checkout
after success; failed, dirty or locked scratch stays with its path reported. An existing
checkout belongs to its caller, and an unsuccessful creation directory is removed only
when empty and unregistered. No broad machine cleanup is performed by these changes.

Sparse worktrees omit irrelevant evidence/reference archives before materialization.
SVG lint reports deliberately absent skip-worktree files as omitted, validates present
files, and fails on malformed XML, ordinary missing/unreadable files or parser/discovery
errors. The earlier process-substitution implementation could print a validator failure
without failing lint; the corrected exit handling makes that failure visible.

The committing, orchestrating, session-cleanup and using-tools skills describe the
retirement and cleanup contract. During integration, the new sparse-checkout instruction
met an adjacent sentence promising a full checkout; that sentence now says sparse
exclusions are used unless the task needs those files.

Verification: all 29 focused retirement, updater, build and sparse-lint regressions
pass, along with 270 CLI checks, 13 identity-wrapper checks, the full Python gate,
documentation lint, headless boot and whitespace checks. No game behavior or visual
asset is changed by the safeguards. The independent initial review reruns the focused
fixtures and verifies silver-ibis's archive counts, artifact identities and selected
timestamps. Final review covers the PR including these records and remaining queue.

Remaining automation stays under teal-ibis: measure peak allocations before choosing
enforced disk-headroom defaults, and attribute browser scratch beyond the already
cleaned disposable profile before implementing further cleanup. These are concrete
followups, not claims that all temporary data is automatically cleaned. Failed-job
diagnostics are intentionally retained for inspection. No installed application,
regular browser profile or arbitrary system cache becomes disposable under this rule.
