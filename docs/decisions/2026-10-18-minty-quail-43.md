# minty-quail — The pause and held-restart suites drive public seams · 2026-11-01


minty-quail's `tests-public-seams.md`, slice 1: `tests/test_pause.gd` and `tests/test_held_restart.gd`. The
player allows the item in slices alongside the other steps "as long as the final result is the same" (inbox #813 in
curly-moose); the item is done suite by suite.

**Built.**
- Neither suite reads a private member of the code under test, and neither calls a frame by hand. An event is
  pushed through the viewport of the screen under test (`Viewport.push_input(event, true)`, so the GUI layer runs
  before the unhandled pass) or through `Input.parse_input_event()` where the engine's own emulated mouse click is the
  point; the two-frame acknowledgement of a tap is waited out in real frames; a button is found by the name the
  scene gives it and pressed where the layout, a frame later, really draws it, instead of being moved and resized by
  the test first.
- The screens' platform is handed in before they enter the tree (`PauseScreen.use_platform`,
  `TitleScreen.use_platform`, `DaySummary.use_touch`, which already existed), so no test writes the screen's
  touch or quit flag.
- Two seams were added:
  - `ModeButton.use_clock(clock: Callable)`: the seconds a hold is measured on. A button never handed one reads
    the wall clock as before. A hold of a full second is a clock that moved a second and a frame the button
    processes; the half-full disc is exactly half full.
  - `TitleScreen.note_restart_requested(at_msec)` takes the tick it stamps (default the moment of the call), and
    `RESTART_GUARD_SECONDS` is public. The guard "the window has passed" is a restart stamped further back than the
    guard, which also leaves the process-wide stamp harmless to the suite's other title screens; the suite no longer
    writes the static and puts it back.
- `tests/ui_screens.gd` is the helper both suites share (a fake clock, the push, the frames, the controls found by
  name); the runner loads only `test_*.gd`, so it is not a suite.

**Rejected.**
- A test-only accessor for each screen's buttons and labels (`restart_button()`, `hint_text()`): the scene's node
  names are its public structure and the game reads nothing of the kind.
- A clock forwarded through `PauseScreen`/`DaySummary` to their restart button: the button is the owner of the hold,
  and a test that needs the clock reaches the button through the tree like a player's finger does.
- Waiting out a real second per hold: about fourteen holds, and a half-full disc read on the wall clock is
  timing-dependent.

**Checks narrowed or merged, and why.**
- The rotated-hover half of the round-button check is dropped. A hover is read only from a mouse on a device with no
  touchscreen, and the layer is rotated only on a touch device in a portrait window (`ScreenOrientation.wants_rotation`),
  so the combination the old test built by setting the screen's touch flag and calling its hover function cannot occur
  in play. Hover is now checked at the square's edges and corners with real mouse motion, upright; the press is
  checked at the same offsets in both orientations.
- `controls._drag_pointer_index == -1` after the dismissing press is merged into the following check, which reads
  what that field is for: the finger's later drift does not re-aim her.
