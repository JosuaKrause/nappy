# minty-quail — The test runner fails a suite that leaves shared state changed · 2026-11-01



minty-quail's `tests-isolated.md`. The player asked for tests "properly isolated and not flaky" (freckled-moose #914) after
`main` went red on a `test_touch` failure seen only behind another suite in the same shard, and answered "yes" to the runner
recording shared state before and after each suite and failing the suite that changed it, naming what changed (inbox #939).
The landing process is unchanged.

**Built.** `tests/shared_state.gd` (`SharedState`) snapshots, before each suite (after `_reset_globals`) and after the frames
that follow it: the tree's `paused`, `Engine.time_scale`, `Input.mouse_mode` and the names of the nodes under the root and
under the runner; each `InputMap` action's events and deadzone; whether `Input` holds each action pressed; every script
variable of the autoloads (`Tuning`, `EventBus`, `Telemetry`, `GameState`, `VisitCounter`) and the connections on each of
their signals; and every `static var` under `src/`, found by reading the sources, so a new static is checked with nobody
adding it to a list. A difference fails the suite with `<suite> left shared state changed, <field>: <before> -> <after>`
(also printed as `LEAK` when found, since a killed shard prints its failures only at the end). `tests/run_tests.gd` calls it.

**Exemptions are fields, never owners.** `SharedState.EXEMPT` names each field that may change, with a one-line reason:
statics memoised from constant data or files on first use (the atlas library, the street network, the event catalogue and the
like), and the fields a booted `main` hands the observers that `_reset_globals` hands back (`Telemetry._config`,
`VisitCounter._config`, `GameSave._config`, the remembered controls). A new field of the same script is checked until it is
listed. A suite that leaves `GameSave._path_override` or a `Telemetry` field other than those changed fails; a scratch suite
that set `GameSave._path_override`, `Telemetry._run_dir` and `VisitCounter._open_tasks`, paused the tree, set the time scale,
added a root node and an `InputMap` action, pressed an action and left a signal connected failed with each named (the scratch
suite is not committed). A connection made to a script rather than an object (`GameSave`'s guarded static handler) is skipped,
since it is connected once for the process by design.

**What the runner resets on purpose.** `_reset_globals` still resets the run state, the trace, the save's override hooks, the
frame recorder, the remembered controls and the title's restart stamp before each suite; it resets nothing more. The
observers' count of a run (`Telemetry`'s run folder, day attempts, attempt and burst serial; `VisitCounter`'s day, open tasks and
run-begun flag; `GameSave`'s operation counter) is moved by every suite that boots `main` or drives a run. Such a suite
declares it with `t.gives_back_observers()` as its first line, and the runner puts those fields back to what they were then
once the suite is over (`SharedState.OBSERVER_FIELDS`); a suite that does not declare it fails if it moves them.

**Leaks the check found on the current suites,** fixed in the suites: `test_touch.gd` and `test_orientation.gd` left the
`pause` action pressed (a touch fed through `_input` presses it through buffered input that the engine applies at the next
frame, after the suite's own `action_release`; they now flush the buffer first); `test_pause.gd` and `test_main.gd` left
`TitleScreen._restarted_at_msec` stamped; `test_sentence_lines.gd` left the tree paused; `test_day_controller.gd` and
`test_protest.gd` left nodes under the runner. Some forty suites that boot `main` or drive a run moved the observers' count and
now declare it. A held `pause` action does not make `test_touch.gd`'s own checks fail (run behind a suite that presses it, its
checks pass), so it is not shown to be the cause of the `test_touch` failure on `main`; the leak is fixed because it is one.

**Not built, and the item stays open for the flaky half.** The ask was tests "properly isolated and not flaky"; this is the
isolated half. Repeated runs and a shuffled suite order (a repeat or `--shuffle SEED` mode in the runner), and three green full
runs, remain in `tests-isolated.md`.

**Cost.** The snapshot reads about forty statics, the autoloads' fields and the node names twice per suite, which is
milliseconds a suite and not measurable against the suites' own times.
