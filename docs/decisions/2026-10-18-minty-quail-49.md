# minty-quail — The test runner fails a suite that leaves shared state changed · 2026-11-01



minty-quail's `tests-isolated.md`. The player asked for tests "properly isolated and not flaky" (freckled-moose #914) after
`main` went red on a `test_touch` failure seen only behind another suite in the same shard, and answered "yes" to the runner
recording shared state before and after each suite and failing the suite that changed it, naming what changed (inbox #939).
The landing process is unchanged.

**Built.** `tests/shared_state.gd` (`SharedState`) snapshots, before each suite (after `_reset_globals`) and after the frames
that follow it: each `InputMap` action's events and deadzone; whether `Input` holds each action pressed; every script
variable of the autoloads (`Tuning`, `EventBus`, `Telemetry`, `GameState`, `VisitCounter`) and the connections on each of
their signals; and every `static var` under `src/`, found by reading the sources, so a new static is checked with nobody
adding it to a list. A difference fails the suite with `<suite> left shared state changed, <field>: <before> -> <after>`
(also printed as `LEAK` when found, since a killed shard prints its failures only at the end). `tests/run_tests.gd` calls it.

**What the runner resets on purpose, and what it now checks instead.** `_reset_globals` still resets the run state, the trace,
the save's override hooks, the frame recorder, the remembered controls and the title's restart stamp before each suite, and
now also `VisitCounter`'s day, open tasks and run-begun flag and `Telemetry`'s run folder and day attempts when no log is open:
those lingered after a suite that booted `main` and the next suite met them. Two lists in `SharedState` are the exceptions,
each entry with its reason: `MEMOS` (statics filled on first use from constant data or files: the atlas library, the street
network, the event catalogue and the like) and `BOOTED_MAIN` (what a suite that boots `main` hands the observers:
`Telemetry`, `VisitCounter`, `GameSave`'s run configuration, the remembered controls). A connection made to a script rather
than an object (`GameSave`'s guarded static handler) is skipped, since it is connected once for the process by design.

**Leaks the check found on the current suites.** One full run of all suites found three real ones, fixed in the suites:
`test_touch.gd` and `test_orientation.gd` left the `pause` action pressed (a touch fed through `_input` presses it through
buffered input that the engine applies at the next frame, after the suite's own `action_release`; the suites now flush the
buffer before releasing, which is the mechanism by which a later suite could meet a held pause), and `test_pause.gd` left
`TitleScreen._restarted_at_msec` stamped (it now gives it back). The rest of what the check reported was an expected hand-over
of one of the two kinds above, plus one real order-dependence that the resets above remove (`VisitCounter`'s open tasks and day
carried from a suite that booted `main` into the next). No suite leaked an `InputMap` action or a signal connection of its own.
A deliberately leaking scratch suite (an added action, a pressed action, a signal connected and left) fails with each named.

**Not done.** The suites that boot `main` still hand the observers a configuration; giving each a teardown instead of the
runner's reset is the follow-on if the `BOOTED_MAIN` list should shrink (it moves with `hidden-statics`, which puts the state
in an owner a suite can hold).

**Cost.** The snapshot reads about forty statics and the autoloads' fields twice per suite, which is milliseconds a suite and
not measurable against the suites' own times. Not built: a `--shuffle SEED` flag for the suite order.
