# minty-quail — SummaryModel, continued(mode), scene recipes through RunFlow, play time in ticks (main-and-state 4c) · 2026-10-30


minty-quail's fourth step of `main-and-state.md`, its last PR of three (minty-quail-20 is 4a, the run
flow and the observers; minty-quail-22 is 4b, the run handed in). Before it, `DaySummary` had four
hand-reset entry points (`show_day_brief`, `show_day`, `show_ending`, `show_finale`) that read the
run and worded every line themselves, kept its own ending and epilogue flags, and sent one bare
`continued`; the run's standing was worded in the summary and again in the pause, and the
resistance tally in the summary; and nine `_recipe` branches in `main` ran a scene recipe beside the
flow, one of them writing the HUD's private fields.

**Built: `SummaryModel`** (`src/run/summary_model.gd`, the domain model). A pure `RefCounted` built
by `brief_for(run, note, section_title)`, `day_over(run, end, section_title)`, `ending(run, which)`
and `epilogue(end)` from the run, the day's end and `Texts`: its heading, title (and whether it is
prose the screen breaks), note, body (its opening prose, which the screen breaks to its label's
width, and the rest formatted around it), morning line and whether the continue shows. `DayEnd`
carries the loss's own sentence (`reason`, the clock's `failure_reason`) and the way out
(`exit_reached`), set in `DayDirector.finish_day()`, so the model reads no clock. The run's standing
(`day_line()`, `nerves_line()`, and `standing_line(run)` for the pause, `Texts.PAUSE_STANDING`
becoming `"%s     ·     %s"`, the same text on screen) and the tally (`resistance_tally()`) are worded
there once. `DaySummary.show_summary(model, raised_in)` replaces the four entry points and only
renders; its `use_run()`, ending and epilogue flags, `is_showing_the_epilogue()`, `back_to_line()`,
`_elapsed_line()` and `_resistance_tally_line()` are gone, and `test_finale` reads the flow's
EPILOGUE.

**Built: `continued(mode)`.** The screen keeps the `RunFlow.Mode` it was raised in (handed by `main`
as `_flow.mode` once the flow has entered it) and sends it with its one continue; `RunFlow.continued(
raised_in)` answers by it and answers NONE when the run has already left that mode, which is also
how a continue with no screen up leads nowhere. `DaySummary`'s dropped late tap (minty-quail-20)
stays the guard; this is the flow's rule.

**Built: scene recipes as configurations of `RunFlow`.** The flow is authored with an
`AuthoredScene` (`src/run/authored_scene.gd`, what the run asks of an authored scene: its map,
whether its lessons are learned, `install()`, `begin()`, `lose_the_attempt()`, its scripted clock),
which `SceneRecipeRuntime` now extends and a test hands bare. `main` keeps no `_recipe`: loading the
recipe and building its runtime is `_author_the_scene()`, which hands it to `RunFlow.author()`; the
day start runs through `RunFlow.start_day(director, spec)`, which has the director start the game's
own day or an authored scene's (`DayDirector.start_authored_day()`, moved from
`main._start_recipe_day()`), begun and never planned; `_start_day()` returns whether the day stands,
replacing the setup-failed early return, and the runtime records `setup_failed` itself on any failed
install; `begin()` and the escape boot's install are `_begin_the_scene()` on `_flow.scene`; the
capture clock asks `_flow.scene.plays_by_script()`; `_city_map()` asks `_flow.authored_map()`; the
escape boot takes its day from an authored scene by `_flow.authored`; `_plan_the_finale_city()` asks
`_flow.plans_the_finale()`; and the lesson skip is `HUD.configure(debug, invincible,
lessons_learned)` from `_flow.lessons_learned()`, the HUD skipping its walking, pause and run lessons
itself, so `main` no longer writes `_teach_left`, `_teach`, `_taught_pause` or `_taught_run`.

**Built: play time counted in physics ticks** (inbox #866 in minty-dolphin, added to this PR on 2026-10-30).
`RunHeader.play_ticks` is advanced by one a tick by `main._physics_process()`, its one owner, only on
a tick the walk stepped (the player, 2026-10-30, on the same note: lag frames where nothing happens
should not count): the flow in WALKING, the day walking or returning, the tree unpaused. The flow's
mode is new to that rule, so a tick that lands after a reload is asked for (the held restart from
the walk, an authored scene's own retry) no longer counts; nothing else changes, since every screen
already paused the tree and the title already returned early. Catch-up ticks after a hitch stepped
the walk and count; `play_seconds()` is the ticks over
`Engine.physics_ticks_per_second`. The save still holds `play_seconds` in seconds, and a save of any
age loads to the nearest tick. `play_seconds` is a function rather than a field because a run part
declares each field once in its data (`tests/test_run_state.gd`); `GameState._end_run()`'s ending
line reads it as a call, a one-line change forced by that. The day's countdown and the resistance
clock are the events PR 4's.

**Built: nothing in the model points up a layer** (review of 8c9577f6). The stars were
`NerveDisplay.stars()` in `src/ui/` and the epilogue's fallback body named `CityEdge.Kind.BRIDGE`, a
world node class. The star formatter is now `Texts.nerve_stars()` (data), read by the model, the HUD
and the tests, and the class `NerveDisplay` is deleted rather than kept as a forwarder (inbox #852 in minty-dolphin);
the fallback is `Texts.FINALE_BODY_DEFAULT`, which is also the bridge's own entry. `Texts.FINALE_BODY`
itself still keys on `CityEdge.Kind`, as it did before this PR. `RunConfig.has_recipe` and
`DevFlags.has_recipe()` had no reader once `main` kept no `_recipe`, and are gone with their checks.

**Choices made where the design was silent, open to overturn.** The orchestrating session's (the
plan of 2026-10-26): the fence widened to `pause_screen.gd` for the one standing formatter; `Texts`
is data and `SummaryModel` reads it; no forwarder or old name kept (inbox #852 in minty-dolphin). The agent's: the
model is built by `main` and handed to the screen, which keeps no run; the body as opening prose plus
a format around it, since line breaking needs the label's font; `DayEnd` carrying the sentence and
the exit rather than the model reading the clock; the authored scene as a base class the recipe
runtime extends rather than callables, since GDScript has no interfaces and a test hands a bare one;
`RunFlow.start_day()` handed the director rather than the flow building one; the authored day start
moved into `DayDirector` beside `start_day()`; the HUD's lesson skip as configuration at composition
rather than a call after install; the resume note (`_resume_gate_note()`) left in `main`, which knows
what opening the save cost; the HUD's debug progress marks (`resistance ***..`, debug builds only)
left as the HUD's own drawing rather than the tally; play ticks rounded on load.

**Tests.** Changed only as far as the code moved: every direct `show_day*`, `show_ending` and
`show_finale` (`test_day_loop`, `test_pause`, `test_held_restart`, `test_main`, `test_run_checkpoints`,
`test_sentence_lines`) shows a model with its mode, built from a `DayEnd`, with the run's day and
nerves set where a check reads them; `test_sentence_lines_render` asks `SummaryModel.clock_line()`;
every summary built from its scene no longer takes the run; every direct
`main._on_summary_continued()` is handed `main._flow.mode`, every test listener on `continued` takes
the mode, and the recipe lifecycle probe emits it; `test_run_flow` hands `continued()` the mode and
an authored flow a bare `AuthoredScene`; the recipe probes read `_flow.scene`; `test_invincible`
passes the lesson flag; the play-time tests drive `_physics_process()` and set ticks
(`test_main`, `test_finale`, `test_run_checkpoints`, `test_save`, the `run_state_scenario` fixture).
New: in `test_hud` the lesson skip, with `lessons_learned` true (no walking lesson at dawn or on choosing the controls, the pause and run lessons taught from the start, the teaching day not resetting the run lesson) and false (all of them said), each check shown to fail when its guard is dropped; in `test_pause` the standing line equal to `SummaryModel.standing_line()`; `tests/test_summary_model.gd` (each screen's text, the tally, the standing line), in
`test_run_flow` a continue from a mode the run has left leading nowhere and the authored

**For the remeasuring step.** Two behaviours meant to change. Play time follows the game rather
than the wall clock: on a machine that drops physics ticks (a frame longer than the engine's steps
per frame), the run's time played now counts only the ticks that ran, where it counted the frame's
whole length. A failed escape-recipe install now records `setup_failed` in the manifest, as a failed
day-recipe install already did; its run quits non-zero either way. Nothing else is meant to change:
every screen shows the same text, and the pause's standing line is the same string.
