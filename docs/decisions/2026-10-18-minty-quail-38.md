# minty-quail — The route rig carries a building run into the city by pressing the run flow's own continue (route-from-the-building) · 2026-11-01

minty-quail's `route-from-the-building` item, the carry-over from events-composed (minty-quail-26), not
the player's ask: a run booted into the escape's building with `--route` waited at the city's brief,
because nobody pressed its continue, and `main` skipped the brief of a city boot with a branch of its own.

**Built.**
- `RunFlow` announces a raised brief (`brief_opened`, with the `DaySpec` it leads into), beside
  `day_started` and `day_planned`, the two it already sends the route rig.
- `RouteRig` answers an escape section's brief a frame after the flow raises it, by calling `main`'s
  `_on_summary_continued()` (handed to it by `use_continue()`) with `RunFlow.Mode.BRIEF`: the continue a
  tap and a key both end in, carried out by the run flow like any other. A day's brief is left alone
  (`spec.section == NONE`); a rig skips a day's by its own boot.
- `main` no longer chooses a branch for the city boot's first screen: `_open_the_first_screen_of_the_escape()`
  raises the brief and the rig presses it. A building won under `--route` builds the city, raises its
  brief, and the rig, built with the city, presses it and walks on to an exit.

**Why this shape.** The press is not an input event: a rig run has every real action binding erased
(`RigLock`), so a `ui_accept` event matches nothing; a first version that pushed one into the viewport
changed nothing, and the run stayed on the brief. Handing the rig the continue as a callable keeps it
off the screen's class (naming `DaySummary` in the rig made `main.gd` fail to parse through a class
cycle). `tests/test_finale.gd` holds three checks, each of which fails with the connection of
`brief_opened` removed: a building run won under `--route` ends walking in the city, a city boot under
`--route` walks without anyone pressing the brief, and without `--route` the city's brief waits.

**Only a section's first brief is pressed.** The rig keeps the sections it has pressed, so a retry brief
raised after a loss is not pressed again. A lost city section ends on its outcome screen, which the rig
never pressed (it is not a brief), so a loss stopped the rig there before this change and still does; the
guard keeps a retry brief from being pressed if a person gets that far. `tests/test_finale.gd` holds a
check that fails without it.

**Left, and still queued.** The item `route-from-the-building` stays in minty-quail's folder, rewritten to
the remainder: the rig is built with the city, so a building boot under `--route` stops on the building's
brief, and nothing walks the building. This change carries a won building into the city, not a building
boot to an exit. Two checks in `tests/test_finale.gd` (the city boot walking, and the city brief waiting
without `--route`) passed before the change and are parity checks for the removed branch.
