# minty-quail — A DayDirector starts and ends the day, and LossCause is pure (main-and-state 3/4) · 2026-10-25


minty-quail's third step of `main-and-state.md`, the refactor's eighteenth PR (PR #860), after the run
state kept in one registered list (minty-quail-14). The item is built as four PRs; this is the third,
then `RunFlow` with `SummaryModel` and the scene recipes as its configurations. A day was built by
`main._start_day()`, about twenty ordered calls private to `main`, so `tests/test_resistance.gd` kept
a copy of the order that could drift from the real one, and its end and the naming of its loss cause
were `main`'s too.

**Built.** `DayDirector` (`src/run/day_director.gd`, run flow) has `start_day(spec)`, the ordinary
day's construction in its old order on the old random streams, and `finish_day(result)`, which does
the won last night's fire, the cause, the charges still running closed, `day_ended`, and for an
ordinary day the calendar's move and the hand-over to the escape, and returns a `DayEnd`
(`src/run/day_end.gd`: finished day, cause, elapsed seconds, section / hand-over / goes-back /
run-over). `main` writes the save and raises the summary from the `DayEnd`, and keeps the section flow
and its own booleans. `start_day()` requires the city (whose events it plans), the resistance, the player, the baby and the
clock; `finish_day()` requires only the clock and the run, the escape's building having no city, and
reads the rest where present; the readout, HUD and route rig are `null` where the game runs without
them, and the director calls them inline as `main` did (observers subscribing instead is PR 4's, open
to overturn). `LossCause` (`src/day/loss_cause.gd`,
domain model) is the cause naming over plain values, no nodes and no globals: `of(result, hard_fail_reason,
struck_by, landed_by_group)`, `hard_fail_suffix`, `crying_suffix`; the world reading that feeds it,
`landed_by_group()` (events, crowd, baby), is the director's. `main._prepare_city_scenery()`,
`_start_the_crowd()` and `_hands_over_to_the_escape()` became `DayDirector.prepare_city_scenery()`,
`start_the_crowd()` and `hands_over_to_the_escape()`, with no forwarder left. `main` builds the
director for the world as it stands each time a day starts or ends (`_new_director()`), because the
world changes between escape sections. The recipe branches (`_start_recipe_day()`,
`_apply_recipe_teaching()`, the early branch of `_start_day()`) stay in `main` for PR 4; none became a
one-line move, and a recipe sets the director's `escape_follows` to false.

**Tests.** `tests/test_day_lost_to.gd` is `tests/test_loss_cause.gd` on `LossCause`;
`tests/test_day_director.gd` runs `finish_day()` on a bare world and a fresh `RunState`;
`tests/test_resistance.gd`'s two tests that copied the day order start day 9 through the real
director on the run seeded `SEED`, whose streams are the ones its `_rng()` drew; `tests/test_finale.gd`
calls the director for the crowd and the hand-over; three other tests changed a name. Callers outside
the fence changed by a name in a comment (`event_bus.gd`, `day_controller.gd`, `save_indicator.gd`,
`park_cordon.gd`, `baby.gd`, three in `event_manager.gd`) and in `docs/TELEMETRY.md`'s loss-cause
lines.

**Choices made where the design was silent, open to overturn.** The orchestrating session's picks:
`DayEnd` returned rather than the director raising screens; no recipe branch moved; the director's run
handle is typed by giving `src/autoload/game_state.gd` the `class_name RunState` (the autoload cannot
share the class name `GameState`), so a test hands a fresh `RunState.new()` and a removed member fails
at parse time. The agent's: the director calls the calendar's operations on the run it is handed
(`begin_day()`, `settled_this_act()`, `current_act()`, `day_rng()`, `finish_day()` and the hand-over
questions) because they live on the autoload and not on a part, moving them being filed in `hidden-statics.md` as the orchestrating session's carry-over from this PR;
`facts` and `attempt_spend` are taken off the run's parts; `main._use_the_day()` hands the readout and
HUD over only when `_day` exists, and every real boot (title, recipe, escape, web) builds `_day`
unconditionally in `_ready()` before any call, so only a script-only `main` in a test reaches it
without one.

**Pinned order.** `tests/test_resistance.gd` `_test_a_day_is_built_in_its_order` builds day 9 on the light real world through the director and fails when the events and the resistance's mark swap, and when `day_started` is announced after the mark.

**Behaviour changes.** None intended: the same calls in the same order on the same streams, every loss
names the same cause, the save format is unchanged.
