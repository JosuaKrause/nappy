# calm-elk — Shrinking the repository history: no rewrite, no LFS, no evidence repository · 2026-11-01 · not from an entry

The player's decision (inbox #923 in tiny-lark), recorded here so that a later
proposal to shrink the history finds the answer instead of asking again.

**What was decided.** The repository's git history is not rewritten, Git LFS is not used (the player's concern is that it costs
money), and `docs/evidence/` does not move to a repository of its own. gentle-rabbit, "Shrink the
repository's history when few PRs are open", which waited for a moment with few open pull requests
because every rewrite needs a force push, is closed with this record.

**Why.** The only benefit of any of the three ways was a faster fresh clone. The bulk of the history
is `docs/evidence/` still on `main` (about 1.1 GB of the 1.24 GB), almost all PNG that `git gc` cannot
shrink, so only moving the evidence out (to LFS or to a repository of its own) would touch it; the
other way, a `git filter-repo` dropping the files no longer on `main`, saves about 110 MB, about 10%.
A rewrite changes every commit hash, which the records, the `v*` tags, every open pull request's
branch and every other clone pay for; LFS may charge for storage and bandwidth, the player's concern; a separate evidence
repository splits the evidence from the commit that cites it. None of that was worth a quicker clone.

**What would make it worth discussing again.** *Proposed by the filer, open to overturn:* a clone that is slow enough to hurt a person or a
cloud session in practice, not the size alone.
