# crisp-owl — The escape clock shows hundredths, every frame · 2026-10-17

[fluffy-kestrel](../playtests/2026-10-17-fluffy-kestrel.md), #742: "No point in showing the timer as
milliseconds in the escape since the refresh rate is lower than that". Asked which precision, the
player (inbox #746 in [woolly-penguin](../playtests/2026-10-17-woolly-penguin.md)): "escape clocke we can try 100s but it's not going to be much better? framerate
is too low? all of this was on phone."

**What was wrong.** The escape's clock is a `DayController`, and M124's throttle (commit 367f94a3)
made a `DayController` emit `day_time_changed` only when the whole second shown changes; the HUD
rewrites its label only on that signal. So the escape's `%d:%02d.%03d` label changed once a second,
its digits after the point frozen at whatever they were when the second flipped.

**Built (PR #749).** `DayController.emit_every_frame`, set by `FinaleController` on its own clock
only, makes the escape emit every frame; a day keeps the once-a-second emission. The escape's HUD
clock reads hundredths through `GameState.format_clock_hundredths()` (`%d:%02d.%02d`), so it still
reads faster than seconds alone, as [M102's brief](2026-09-09-M102-the-finales-brief-and-the-collisions-the-player-answered.md)
asked. `format_clock()` is unchanged, so the ending screens' run length, the escape's own last line
and the run log keep milliseconds ([M107](2026-09-11-M107-the-run-clock.md)).
`tests/test_day_controller.gd` holds both emissions and the two formats.

**The player's question, answered by the arithmetic.** At 30 fps a frame lasts 33ms: with hundredths
the last digit changes on every frame, by about 3, and the tenths digit every third frame; at 60 fps
the last digit moves by about 1.6 a frame. So on a phone hundredths are a flicker more than tenths
would be, and the old milliseconds were never visible either way. Tenths remain the alternative if
the flicker reads as noise.

**Choices open to overturn:** hundredths truncate rather than round, as the day clock does; the
switch is a flag on the controller rather than a new signal.
