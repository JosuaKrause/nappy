## M171, the ground — built 2026-09-20

A consumer move of the milestone, pull request #254. The agent that began it was cut off by a
usage limit twelve minutes in; a second agent took over its uncommitted worktree, reviewed both
inherited files against `origin/main` and finished the item.

**Built.** `assets/ground_tileset.tres` references no picture: each `TileSetAtlasSource`
carries its picture's baked region name as its `resource_name` (`tiles/road`) and no texture.
`GroundLayers.build_tile_set()` reads `AtlasLibrary.page_image(&"ground")` once per build —
once per city build and once per day repaint — takes every base, overlay, damage stencil,
grass feature and whole authored tile as a `get_region()` of that CPU-side image, composes as
before, plans the sheet with `AtlasLibrary.plan` (the bake's MaxRects packer) and uploads it
once; every source points at that one texture through `margins`. The second runtime packer,
`pack_into_one_texture()`, is gone. The presentation mode is the bake's: the compositor asks
`AtlasLibrary.bake_mode()`, and an SVG bake carries whole authored tiles and composes nothing
but the route-kerb tint.

**The compositing stays at runtime**, as the player decided: nothing composed is on the page.

**The tile declarations left the `.tres` with the textures.** A `.tres` can only declare a
tile for a source that has a texture, and the texture is now the composed sheet, which does
not exist until the upload. The authored file is an id, a cell size and a region name per
source; the upload creates the cells from the picture's width.

**Pixel identity.** A throwaway suite wrote a SHA-256 per source and tile, read through
`get_tile_texture_region()`, from `origin/main`'s compositor and from the branch on the same
bake. Default bake: 238 lines, 237 identical; SVG bake: 134 lines, 133 identical. The one
difference in each is the whole-sheet line — 424×444 against 2035×100, and 240×342 against
2047×67 — which is the packer change. `tests/test_atlas_ground.gd` is the permanent check: its
reference is rebuilt from the page and the manifest with `Image.blend_rect` and `rotate_90`,
never from `GroundLayers`, and it was checked against two mutations (every component rotation
forced to 0 fails 16 sources; the upload's margin shifted one pixel fails 146 cells).

**Measured.** `build_tile_set()` over eight consecutive headless calls on one machine:
`origin/main` 70–80 ms first build and 49–57 ms warm; the branch 32–38 ms and 31–34 ms. GPU
readbacks per build went from roughly seventy — one per composed layer and one per source —
to one, the page's own. The run log's `texture` line reads `ground composed: …` and times the
whole build, where `ground packed: …` timed the pack alone.

**Two traps in comparing bake modes.** `tools/test.sh` cannot run the SVG side, because it
re-bakes to PNG first; the suite runs through the engine directly. And straight after
`tools/bake-atlases.sh --svg`, with `.godot/imported/` still holding the other mode's page,
every tile differs — the region table is the new bake's and the pixels the old one's, at a
page of the same size, so nothing fails loudly. The import pass has to run between.

**Open to overturn.** A source whose region the bake does not carry keeps no tiles and draws
nothing, where it used to fall back to its authored SVG — no individual texture is left to
fall back to. It is a `push_error`, so the test gate is red for it; unreachable today, since a
bake carries every member of the group in either mode, and `test_atlas_ground` fails by name
if a name stops being a member. The fallback from an incomplete *recipe* to the whole
authored tile was still there after this pull request, and is what "M171, the ground page
per bake mode" removes. The sheet's separation went from 1px to
2px with the packer.
