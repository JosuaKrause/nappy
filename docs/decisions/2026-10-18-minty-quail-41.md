# minty-quail — The run calendar leaves the GameState autoload (hidden-statics, part 1) · 2026-11-01


minty-quail's `hidden-statics.md`, its second half: the run calendar's operations leave the `GameState`
autoload. The first half, the `static var`s that hold hidden globals, is still the item.

**Built.**
- `RunCalendar` (`src/run/run_calendar.gd`, a plain `RefCounted`, the model layer) holds what the
  calendar reads and writes: the registry and the header, settled, resistance and facts parts it is
  handed, the run's mode (`hard_mode`) and its `checkpoint`, and the trace. `RunState` builds one over its
  parts (`run.calendar`). It owns `day_rng()`, `begin_day()`, `finish_day()`, `settled_this_act()`,
  `settled_yesterday()`, `remember_where_she_settled()`, `current_act()`, `is_final_day()`,
  `earned_good_ending()`, `choose_mode()`, `checkpoint_day()`, `is_checkpoint_day()`,
  `a_loss_goes_back_to_the_checkpoint()`, `regain_a_nerve()`, `regain_a_nerve_for_a_won_day()` and the
  private checkpoint, go-back, end-of-run and give-back-the-attempt steps. `RunState` keeps the parts, the
  snapshot, `start_run()`, the resistance steps, `run_rng()`, `city_rng()` and the clock formats.
- `DayDirector` is handed `(calendar, facts, spend, config)` and no `RunState`; `DevRig.for_spawn_target()`
  is handed the `RunHeader`, the one thing it read of the run.
- `GameSave.run_data()` and `restore_run_data()` take the registry (`RunStateRegistry`) instead of the run:
  the calendar hands `GameSave` the registry for a checkpoint, so a fresh `RunState.new()` keeps its
  checkpoint to itself. The save format is unchanged (`tests/test_save.gd` and
  `tests/test_run_checkpoints.gd` pass, the checkpoint equals the file's keys).
- Every caller moved to `.calendar.` in the same change (about 55 files, a mechanical rename); no
  forwarder is left on `RunState`. The one layer exception for the registry handing itself to `GameSave`
  moved to the calendar, which names `GameSave` three times (the checkpoint's two directions and the
  save cleared when a run ends).
- Going back from a run's last nerve to checkpoint zero no longer calls `start_run()`: it resets the
  registry, keeps the seed and who pushes the pram, and clears the mode and checkpoint, which is what
  `start_run()` did to a normal run on its own seed. The one difference is the console line
  `[GameState] run started` that call printed, which the go-back no longer prints.
- Nothing changed value or behavior.
