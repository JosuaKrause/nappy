# minty-quail — The run calendar leaves the GameState autoload (hidden-statics, part 1) · 2026-11-01


minty-quail's `hidden-statics.md`, part 1: the run calendar's operations leave the `GameState`
autoload. The statics half, the `static var`s that hold hidden globals, is still the item.

**Built.**
- `RunCalendar` (`src/run/run_calendar.gd`, a plain `RefCounted`, the model layer) holds what the
  calendar reads and writes: the registry and the header, settled, resistance and facts parts it is
  handed, the run's mode (`hard_mode`) and its `checkpoint`, and the trace. `RunState` builds one over its
  parts (`run.calendar`). It owns `day_rng()`, `begin_day()`, `finish_day()`, `settled_this_act()`,
  `settled_yesterday()`, `remember_where_she_settled()`, `current_act()`, `is_final_day()`,
  `earned_good_ending()`, `choose_mode()`, `checkpoint_day()`, `is_checkpoint_day()`,
  `a_loss_goes_back_to_the_checkpoint()`, `regain_a_nerve()`, `regain_a_nerve_for_a_won_day()` and the
  private checkpoint, go-back, end-of-run and give-back-the-attempt steps. `RunState` keeps the parts, the
  snapshot, `start_run()`, the resistance steps, `run_rng()`, `city_rng()` and the clock formats.
- `DayDirector` is handed `(calendar, facts, spend, config)` and no `RunState`; `DevRig.for_spawn_target()`
  is handed the `RunHeader`, the one thing it read of the run.
- `RunStateRegistry.run_data()` and `restore_run_data(data)` are the registry's own snapshot (the parts in
  the shape a save and a checkpoint carry); `GameSave.run_data()` and `restore_run_data()` are gone and
  `GameSave.file_data()` and the load call the registry. The calendar reads and writes its checkpoint
  through the registry and names `GameSave` nowhere, so the layer exception for it is gone. A run's end
  clears the save through `GameSave.clear_when_a_run_ends()`, which `main` calls before a boot's charge and
  which listens to `EventBus.run_ended`; `_end_run()` no longer calls `GameSave.clear()`. The save format is
  unchanged (`tests/test_save.gd` and `tests/test_run_checkpoints.gd` pass).
- Every caller moved to `.calendar.` in the same change (about 55 files, a mechanical rename); no
  forwarder is left on `RunState`.
- Going back from a run's last nerve to checkpoint zero is the registry's reset: the header keeps the
  run's seed and who pushes the pram, and a normal run has no checkpoint to clear and is not in hard mode.
  It no longer calls `start_run()`, so the console line `[GameState] run started` is no longer printed
  on that path.
