# minty-quail — The run handed to GameSave and the readers (main-and-state 4b) · 2026-10-30


minty-quail's fourth step of `main-and-state.md`, its second PR of three (minty-quail-20 is 4a, the
run flow and the observers; 4c is `SummaryModel`, `continued(mode)` and the remaining scene-recipe
branches). Before it, `GameSave` was a namespace of statics that read `GameState.run_parts`, and
every reader but `City` and `DayDirector` took a part off the `GameState` autoload by name, `main`
among them.

**Built.** `main` takes the autoload once (`var _run: RunState = GameState`, beside the `_spend` and
`_facts` it already took) and reads the run through `_run` everywhere. It hands `_run`, typed
`RunState`, to every reader it builds: the HUD, the summary, pause and title screens
(`use_run()`, before each enters the tree, since the HUD draws its header and resistance line in
`_ready()`), `RunSession` (`setup(…, run)`), which hands it to its `TelemetryObserver`
(`setup(run, …)`), `FrameTrace` and `FrameRecorder` (their `setup()`), `DayController`
(`setup(map, player, run)`), `VisitCounter` (`configure(config, run)`), `RouteRig` (`setup(…, run)`),
and the scene recipe runtime (`configure(result, config, run)`), which hands it to
`SceneRecipeDraft.compose()`. `DevRig.for_spawn_target()` takes it as a parameter from `DayDirector`
and `RouteRig`. The three clock formatters are called on the class (`RunState.format_clock_seconds()`),
since they read no run. **`GameSave` is handed the run on every call that reads or writes one**:
`write`, `try_resume`, `load_in_memory`, `file_data`, `run_data`, `restore_run_data` and their
ungated seams; `clear()` and the web flush read none. `RunState` hands itself for its checkpoint.
No forwarder or old signature is kept (the player: no legacy shape kept, inbox #852).
 The events and the resistance
still read the autoload, as the queue entry's carry-over says, and nothing is kept on it for them.

**Left open: the city's posters.** `PosterWalls` (the run's seed and its `posters` day stream) and
`PosterArt` (whether the neighbor was taken, for the crossed wanted notice) still read the autoload.
`City.build()` builds `PosterWalls` and hands it the `PosterState` part (minty-quail-14), and
`Building._draw_posters()` draws through `PosterArt.texture_for()`; neither `City` nor `Building`
was in this PR's fence, and handing the two the run reaches through both. The queue entry holds it.

**Choices made where the design was silent, open to overturn.** The orchestrating session's: the
readers above handed the run typed `RunState`, `GameSave` handed it rather than reading the
autoload. The agent's: `GameSave` handed the run per call rather than held by an instance, because
the web flush and its operation ids outlive the scene reloads that free the `main` holding a run, and
`RunState`'s own checkpoint calls `run_data()` and `restore_run_data()`, so an instance per boot would
need a second, page-lived half and a save object inside the run; the screens built from scenes take
the run through a `use_run()` beside their `use_platform()`/`use_touch()`, the nodes with a `setup()`
through it; `TelemetryObserver` is handed the whole run where it reads only the day it plans, to keep
the one rule.

**Tests.** Changed only as far as the code moved: every `GameSave` call that reads or writes a run
is handed `GameState` (`test_save` above all, `test_run_checkpoints`, `test_run_state`,
`test_finale`, `test_park_return`, `test_pelican`, `test_resistance`, the `run_state_scenario`
fixture); every screen a suite builds from its scene is handed the run as it is built; the suites
that build a `DayController`, `RouteRig`, `RunSession`, `FrameRecorder`, scene recipe runtime or
counter hand it in the call that builds or sets it up, or set the private member beside the others
the suite already wires by hand (a bare route rig, the observer's day test, the recorder's
environment test, the mast test's runtime, the counters built from the script); the test counters
(`RecordingCounter`) are handed the live run on construction; `test_save`'s read of `main`'s source
looks for `_run.finish_day(…)`; the runner's reset hands `VisitCounter` the live run with no
configuration, since the bus reaches it in suites that boot no `main`.
