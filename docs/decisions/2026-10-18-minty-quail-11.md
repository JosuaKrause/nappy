# minty-quail — The developer readout, the return window and the rig lock are their own nodes · 2026-10-25


minty-quail's first step of `main-and-state.md`, the refactor's eleventh PR (PR #846). `main.gd`
(3,077 lines) carried, beside the run flow, the developer's readout and its keys, the half second of
ignored input after the game gets focus back with the browser's listeners behind it, and a rig's
lock-out and quit deadline; `--touch` in `TouchInput` and `--web` in `QuitOption` read the command
line themselves. The item is built as four PRs, each reviewed and merged before the next; this one
is the first, in the order the orchestrator chose: these nodes, then run state kept in one place, then the `DayDirector` with `LossCause`, then `RunFlow` with `SummaryModel` and the
scene recipes as its configurations.

**Built.** `DebugReadout` (`src/dev/debug_readout.gd`) is the developer's furniture over a run: the
right-hand readout, rebuilt every 0.25s, the frame-time graph, the `?debug=1` note, the debug
overlays (`DebugLayers`) and the day's routes (`RouteLines`), the number keys `1`–`6` and the
snapshot and burst keys. It is a `Node2D` at the origin, so the overlays draw in world space on the
debug layer as they did under `main`, and it runs through a pause. It is handed everything it reads
and asks nothing of `main`: `setup(config, label, layer, run, session, screen_name)` at boot,
`watch(player, baby, day)`, `show_the_world(events, crowd, world, map, city)` once per world (the
escape re-points it when she walks out of the building), `draw_routes()`/`refresh_routes()`,
`use_the_day(spec)`, `watch_frames(recorder)`, and `open_the_title()`/`close_the_title()`/
`show_for_the_walk()`; the frame trace asks it `readout_on()` and `graph_on()`. Its gates are
unchanged. `ReturnWindow` (`src/ui/return_window.gd`) is the half second of ignored input after a
return (inbox #534 in misty-toad): the engine's focus notifications, the page's `visibilitychange`,
`focus` and `blur`, the rule that a return needs a departure, and the end read off the wall clock
every frame and on leaving the tree; a departure emits `left_the_game`, which `main` connects to its
own `_pause_on_focus_lost()`. `RigLock` (`src/dev/rig_lock.gd`) is a rig's lock-out (PLAYTEST-133):
the no-focus window flag, the `InputMap` erase, the `_input()` filter that lets only a rig's own
`DEVICE_ID_EMULATION` presses through, and the quit deadline in wall-clock or game seconds; it is
added first thing in `main._ready()`. `--touch` and `--web` are `RunConfig.touch_forced` and
`web_preview`, a debug build's like every dev flag; `TouchInput.available(config)` and
`QuitOption.available(config)` take the config, and `main` reads the touch answer once and hands both
answers to the HUD, the day summary, the touch controls, the title and the pause screen
(`use_touch()`, `use_platform()`) before each enters the tree. `main` keeps the focus-pause policy,
Esc, the frame trace and record it builds, and the readout's label and layer in its scene;
`main.gd` is 2,436 lines.

**Choices made where the design was silent, open to overturn:** `DebugReadout` and `RigLock` live in
`src/dev/` and `ReturnWindow` in `src/ui/`; the snapshot keys moved with the layer keys, their
context line asking `main` what screen is up through a handed Callable; the readout is handed
`GameState` as the run whose seed and calendar day it names; the focus-pause policy stays on `main`,
whose screens it is about, and the window only announces the departure; the screens take their
platform answers through two setters, keeping the platform's own answer when built outside a boot;
`_add_debug_layers()` and `_add_route_lines()` stay on `main` as one-line calls into the readout; the
58 hidden statics the review counted are split out of this item into `hidden-statics.md` by the
orchestrating session, beside `tests-public-seams.md` in the folder's order.

**For the remeasuring step:** no behaviour is meant to change. Two orderings within a frame move,
read off the code and not measured: the readout's text is rebuilt in the readout's own `_process()`,
after `main`'s in the same frame, and a rig's deadline is checked in `RigLock._process()` rather than
first thing in `main._process()` (the quit takes effect at the frame's end either way).
