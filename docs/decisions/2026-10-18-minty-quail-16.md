# minty-quail — The mover is a LaneMover, the drawing is a walker look and a car look, the crowd hands in the screen · 2026-10-25


minty-quail's `shared-components.md`, the second of two PRs for its part "Walker and car are one
class" (PR #856; the first is the record `2026-10-18-minty-quail-12.md`, PR #847). `CrowdAgent` held
the lane movement both kinds share, the crowd member's excitement, halo and caret, and a drawing
that chose each kind's picture, sector, redraw key, bob and paint by asking `kind` in 11 places;
and it reached for the camera, the viewport's drawn box and the frame record's statics without
being handed them.

**Built** (`src/crowd/`). `LaneMover` (`lane_mover.gd`, `extends Node2D`) holds the lane state, the
look-ahead, the held step, placement and recycling, the junction and queue questions, `heading()`
and `velocity()`; it has no picture, no excitement and no halo, and reaches the crowd member only
through six do-nothing hooks (`restart_the_picture()`, `advance_the_picture()`, `_dress()`,
`_end_the_frame()`, `_entry_picture_clearance()`, `_kind_installed()`) called at the points of the
frame the code ran them before. `CrowdAgent` extends it and keeps the excitement methods (untouched
and still callable by name from `EventInstance`), the halo, the caret, the jolt and the redraw gate.
`AgentLook` with `WalkerLook` and `CarLook` take the 11 drawing branches, the authored view tables
and the state only a picture has (the sector, a walker's stride, a car's travelled ground);
`kind` installs a look beside the strategy. The car's shadow shape and its constants moved to
`CarStrategy`. `Crowd` owns a `CrowdView` (the camera square `_beyond_every_view()` asks, and the
`DrawnView` box the redraw gate asks) and a `CrowdTiming` (the frame record's crowd bucket and
draw count) and hands both to every agent it makes, through one `_make_an_agent()` in place of three
copies of the same assignments. `EventInstance` keeps `DrawnView` and the `FrameRecord` statics.
The 5 excitement field-number branches are left for `ExcitementSource`. The moved docstrings state
what is true now. The design docs that named moved members (`ARCHITECTURE`, `GRAPHICS`,
`TELEMETRY`, `CITY`, `MECHANICS`) name where they live. About forty comments in the crowd tests
and probes that named a moved member with no class name it (inbox #852 in minty-dolphin).

**The crowd tick's cost, as measured.** The parity probe's per-tick medians of the agents' own
frames and of `Crowd._physics_process()`, headless debug build on an Apple M2, base and head
interleaved per round (base first), `LANE_PARITY_REPS=2`, all 12 cases, head at `86954fa2`. Each
figure is the mean over the 12 cases of head's median over base's; three other agents' test suites
ran on the machine throughout, so its speed moved between rounds:

| Round | Load average ending the head run | Agents' frame | Crowd tick |
|---|---|---|---|
| 1 | 5.4 | 0.974 | 0.981 |
| 2 | 4.5 | 1.008 | 1.009 |
| 3 | 8.8, rising from 7.0 | 1.168 | 1.143 |
| 4 | 8.7 | 1.022 | 1.026 |
| 5 | 9.2 | 1.026 | 1.022 |
| 1, 2, 4, 5 together | | 1.007 | 1.010 |

Round 3 is excluded: the load climbed during its head run, which ran after its base run, and the
ratio shows it. The four rounds support head within about 1% of base (from 0.974 to 1.026 by
round), not "no slower". The first build, before the hook edits, measured 1.055 (agents' frame) and
1.047 (crowd tick) in two rounds at load 5.0 to 6.0, and 1.107 and 1.083 with the looks, against the
same base. **Why:** an external call to a method defined in the base script walks the script chain
before it finds it. A micro-benchmark on the same machine (headless, 1M calls, a `Node2D` subclass of
a `Node2D` subclass) measured a call from outside to an inherited method at about 136 ns against about
116 ns for a method on the leaf class (+17%), a call from inside the base to its own methods at no
difference, and an inline read of `position` in place of a call to `_along()` at no gain (289 ms
against 263 to 294 ms per 1M). A tally of the external calls into `LaneMover` methods came to about
3.7 per agent-frame (`_along()` 0.86, `_cross()` 0.86, `velocity()` 1.0, `_segment_is_shut()` 0.56
and a few more); the before and after ratios (about 1.05 down to about 1.01 once the hooks were merged) and the tally
suggest that the larger part of the first build's cost was the extra hook calls every agent pays every
frame, which the edits removed (an inference: the micro-benchmark measured an inherited call, not the
hooks' share): the clocks and the redraw share one end-of-frame hook, the
screen test is inline, and the look is handed the velocity the agent already computed. The release
build is not measured: the repo has no way to run the probe on an exported release build.

**The player's answer on the cost** (board `crowd-tick-cost`, inbox #852 in minty-dolphin): "let's eat the cost for

**Choices made where the design was silent, open to overturn:**
- The mover is a base class and the looks are composed (the orchestrating session's pick; the
  player's answer on the cost leaves it standing).
- `CrowdAgent._init()` calls `super()`; without it a bare `CrowdAgent.new()` never ran
  `LaneMover._init()` and had no strategy until its `kind` was set.
- `_clock` and the jolt countdown run down in the crowd member's end-of-frame hook, not at the start
  of the frame: nothing in the frame body reads either, and every frame that is not skipped ends
  there once.
- No forwarder or old name is kept only so that callers or tests need not change (the player,
  inbox #852 in minty-dolphin: "Don't let legacy implementations prevent you from establishing a clean design"). The
  crowd member's `_draw_body()`, `_body_bob()`, `travel_axis()` and `_redraw_if_the_picture_changed()`
  are removed: the halo is built with the look's `draw_body` and `bob`, `DebugLayers` and `CarLook` read
  `heading()`, and the tests that step a picture by hand call `_end_the_frame(0.0)`. What remains
  for another agent's fence: none in `src/crowd/`; the comments in `src/events/` that name moved
  members (queue carry-over).
- `CrowdView` reads the shared `DrawnView` and `ScreenOrientation`, which are view-layer; accepted
  because `DrawnView` is shared with `EventInstance` (the orchestrating session's pick; the cleaner
  version is a queue carry-over).
- The car's shadow shape and constants live in `CarStrategy`, which asked for them, not in the look.
