# minty-quail — The run's state kept in one registered list · 2026-10-25


minty-quail's second step of `main-and-state.md`, the refactor's fourteenth PR (PR #853), after the
developer readout, the return window and the rig lock (PR #846). The item is built as four PRs, each
reviewed and merged before the next; this one is the second: run state kept in one place, then the
`DayDirector` with `LossCause`, then `RunFlow` with `SummaryModel` and the scene recipes as its
configurations. A run's fields were kept by hand in up to six places each (`save_snapshot`,
`restore_snapshot`, the `_SAVE_FIELDS` list, the `_dawn_*` copies, the lost day's give-back and
`GameSave`'s riders), so a field missed in one was silently not given back or not saved.

**Built.** `src/run/` (the domain model, layer 2) holds `RunSubState`, the interface `PosterState` and
`PelicanState` already had (`reset`, `photograph`, `give_back`, `to_data`, `restore`) plus the slot the
save puts the part in (`STATE`: inside the `"state"` snapshot, every key required; `RIDER`: flat beside
it with a default for absence; `NESTED`: under its own key). The parts are `RunHeader` (seed,
presentation, day, nerves, ending, play time), `ResistanceRunState` (steps, progress, sabotage, the
package, with their dawn copies), `AttemptSpendState` (consumed one-shots, scars, block arcs, with
their dawn copies), `SettledState`, `RunFacts` (the escape section, the used alley tiles, the fenced
park), and `PosterState` and `PelicanState` unchanged in place. `RunStateRegistry` is the one list,
`GameState.run_parts`: `start_run` resets it, the dawn and a won day photograph it, a lost day gives
it back, and `save_snapshot`, `restore_snapshot`, `snapshot_is_complete` and
`GameSave.run_data`/`restore_run_data` walk it, so `_SAVE_FIELDS` and the hand-kept copies are gone.
Readers use the owning part (`GameState.header.day`, `GameState.attempt_spend.scars`): the callers
and tests in this change's fence moved to the parts' own API, about 1,270 lines in 90 files. Eleven
forwarding properties remain on `GameState` (`run_seed`, `day`, `resistance_progress`,
`consumed_one_shots`, `completed_resistance_steps`, `failed_resistance_steps`, `scars`, `city_state`,
`sabotage_done`, `resistance_carrying_package`, `completed_resistance_alley_tiles`), only for files
another change owns: `src/events/**` (event_manager, event_def, event_catalogue, event_scheduler,
event_director), `src/resistance/**` (resistance_director, happenings, resistance_steps),
`tests/test_resistance.gd` and `tests/test_event_manager.gd`; they go when those read the parts.
`main` takes `_spend` and `_facts` once and uses them for 18 reads, `main._new_city()` hands `City`
its `run_posters`, `run_spend` and `run_resistance` (a city built outside a boot, as the tests do,
falls back to `GameState`'s parts at the declaration), `PosterWalls.setup` takes the `PosterState`,
and `Blackout` and `TelemetryObserver` read the sabotage flag and the block arcs through the city.
`ARCHITECTURE.md` describes the registry.

**The fixture.** `tests/fixtures/run_state_saved_by_main.json` is `GameSave.file_data()` of the run
`tests/fixtures/run_state_scenario.gd` builds, with a value in every field, and of the same run after a
lost day, dumped on `e1cc7c7f` (the commit the branch is cut from, before any change) by a throwaway
probe that ran the scenario under `tools/test.sh`; the probe is not kept, and the fixture is the
branch's first commit. `tests/test_run_state.gd` replays the scenario on the new build and expects the
same file key for key (all but `build`), the same file after a lost day, the fixture loaded through
`GameSave._read_now()` to resume and write the same file, and a lost day after that load to give back
the same; it also checks the registry holds every part `GameState` declares (a part declared and not
registered is named), each part gives back its photograph, writes one key per field it declares and
reads back what it wrote through JSON.

**Choices made where the design was silent, open to overturn.** The orchestrating session's picks:
the core scalars are a registry entry (`RunHeader`), `GameState` keeps forwarding properties only
for readers in other agents' files (the player: no legacy shape kept, inbox #852), `GameSave` stays static and walks the registered parts
(injecting the registry into the save belongs with `DayDirector` and `RunFlow`), and the sub-states
live in `src/run/` while `PosterState` and `PelicanState` stay where they are. The agent's: `settled_in`
is its own part and the escape section, used alleys and fenced park share `RunFacts`, because a part
has one slot and these ride at different places in the file; a part's `reset()` leaves its dawn copy
at the empty run; registration is `run_parts.register(...)` at the declaration, and an unregistered
part is caught by `RunStateRegistry.unregistered_in()` in the suite rather than at compile time;
`City`'s three `run_*` fields are handed by `main._new_city()` and fall back to `GameState`'s parts
at the declaration for the cities tests build (about thirty test and probe files instantiate one); the one-key-per-field test counts a part's script variables against its `to_data()` keys.

**For the remeasuring step:** no behaviour is meant to change in play. Three differences, read off the
code and not measured: `start_run` resets the attempt-spend dawn copies, which kept the previous run's
values until the first `begin_day()` (a bug fixed on purpose). It shows in the save written when a
normal run runs out of nerves before its first checkpoint, which goes back through `start_run()`:
that save's three attempt-spend dawn copies (`_dawn_consumed_one_shots`, `_dawn_scars`,
`_dawn_city_state`) are empty instead of the lost day's values, with no effect in play, since that
save resumes between days and the next dawn photographs again; on a lost day `resistance_progress_changed` is emitted after the whole
give-back instead of between the resistance and the rest; and `snapshot_is_complete` derives its
required keys from what the parts write, the same 23 keys.
