# minty-quail — The first third of the parked probes are typed · 2026-11-12

**The ask.** Test code is typed as the code it tests is ("we type when we can", inbox #1280 in
olive-ferret), and a test reads its subject only through methods (inbox #1182 in gray-dolphin):
`typed-everywhere.md`, one pass per module. This pass is the first third of the parked probes under
`tests/probes/`, the measurements run by path and never by the runner or CI, from `basement_meter` to
`m118_crash_gap`. Its search is none: it types and deletes lines and converts no read.

  table gives each line): `basement_meter`, `calm_pelican_day13_guard_walk`, `calm_pelican_day13_roadblock`,
  `calm_pelican_fields_layer_cost`, `charger_warning`, `cordon_placement_fingerprint`,

  `m108_walker_stride_sheet`, `m110_bodies`, `m117_decay` and `m118_crash_gap`. No helper a probe loads changed,
  and nothing under `src/`.
- **Typing**: loops name their element types (`CrowdAgent.Kind` for the enum's values, `Vector2i` for tile keys);
  row builders answer `Array[Dictionary]`, or `Array[Vector2]` in `m100_map_edge_entries`; a value out of a
  Dictionary, a `get()` or a nested collection goes into a typed local before a method is called on it.
- **Six checks that can only pass go** (writing-tests, "What a test holds"): a `t.check(true, ...)` each in
  `downy_otter_sealed_alley`, `m100_map_edge_entries`, `m108_event_strides_sheet`, `m108_walker_stride_sheet`,
  `m110_bodies` and `m117_decay`. None moved.
- **Read by name, which the tool cannot see**: `entity_frame_profile_observer` reads `Main`'s private `_readout`,
  `_run_log`, `_day`, `_city` and `_player` through `get()`, no method of `Main` answering them;
  `ground_frames_matched` reads `SceneryGround.pending` through `get()`, no method answering it;
  `lazy_scenery_measure`'s `spans` is a field of the probe's own timed city (`tests/probes/lazy_scenery_city.gd`),
  not of a class under `src/`. No probe writes a script out from a string.

## Parity

Probes are not run by CI, so each was run by path at `origin/main` (da510b555) and at the head, one at a time,
and the outputs compared. Sixteen print the same lines but for the run's time and, in the six that lost a check,
its count; the two stride sheets write byte-identical pictures at both revisions. `basement_meter`,
`calm_pelican_day13_roadblock` and `lazy_scenery_measure` print the same lines once timing, memory and backtrace
line numbers are set aside. `lazy_scenery_routes` draws a fresh run seed on each boot (two runs of main drew two
seeds), so its figures do not compare; its four checks pass at both. `entity_frame_profile`,
`entity_frame_profile_observer`, `ground_frames` and `ground_frames_matched` are not runner probes and error the
same way under `tools/test.sh` at both revisions; launched their own way, `entity_frame_profile` writes the same
metadata and first row at both, `ground_frames` stops at its own two-minute deadline at both, and
`ground_frames_matched` needs a window, the census standing for its parse.

**Found, not changed**: `m108_event_strides_sheet` writes the two pictures under
`docs/evidence/m108-event-strides-2026-09-12/` with content that differs from the committed files, at `origin/main`
as at the head; the walker stride sheet matches its committed pictures.
