# minty-quail — The field-read check: a change may not add a read of another class's field · 2026-11-07


minty-quail's `field-reads.md`, its first part, in #1190: the check the conversion shrinks, built
first, as the board's field-read-check proposed and the player accepted ("yes", inbox #1182 in
gray-dolphin). The conversion stays in the item.

**Built.**
- **`tools/check_field_reads.py`** fails a read or write of `receiver.name` under `src/` when the
  receiver's class is another `src/` class and `name` is a `var` that class or an ancestor
  declares. The receiver's class is resolved by static reading: `self`, `class_name`, the
  autoloads, names typed where they are declared, `Foo.new()`, a typed return, typed-field chains,
  `x := a.b()` and `as Foo`. Methods, signals, constants, enums and engine properties are not
  breaches, and neither is a class's own field, an inner class reading its outer one, or an
  ancestor or descendant (designing-classes, "Fields are not API", inbox #1173 in gray-dolphin).
- **`tools/field_reads.txt`** lists today's reads, `# [Class] path` groups of `<reader file>
  <field>` lines, generated by `--write`. A read not listed fails, a listed line with no read fails
  as `REMOVE`, and with `--base` an added line fails unless a renamed reader file carries it. CI's
  `gates` job runs it against the pull request's base.
- **Measured at its base:** 1638 lines over 103 classes read. By the reader's layer: simulation
  748, the composition root 219, the model 212, the world 149, data 116, observers 106, run flow
  46, the view 42. Most read: `EventDef` 307, `EventInstance` 217, `CityMap` 181, `City` 67,
  `LaneMover` 58, `DaySpec` 55, `EventWorld` 55, `RunState` 48, `WorldMap` 44, `Building` 38.

**Rejected.** A merge tool like `merge-test-only-members.py`: the list is a function of the tree, so
a conflict is resolved by taking either side and running `--write`, and `--base` still fails any
added line.

**Open to overturn:**
- a receiver whose class cannot be told is skipped, not failed (2450 uses of a name some class
  declares as a var, mostly engine properties);
- a line carries no count, so a second read of an already listed field in the same file passes,
  and review reads the diff for it;
- an autoload with no `class_name` is grouped under its autoload name.
