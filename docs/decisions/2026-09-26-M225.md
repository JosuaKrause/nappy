## M225 — The counter counts every attempt, a key player, and a torn poster's chase · built 2026-09-26

*([PLAYTEST-143](../playtests/PLAYTEST-143.md), statements 9–11; [PLAYTEST-144](../playtests/PLAYTEST-144.md),
statements 13 and 28: "no, even current run wouldn't work if the player dies multiple times on the
same day" · "we need a telemetry item for ripping posters and pursuit triggered by poster ripping" ·
"is telemetry currently correctly identifying when a player plays with keys?" · "use this for nappy
stats. for the site visit stat use the old account".)*

Built on PR #368, on top of M208 (the counter says what ended a day and what she met) and M209
(Claude reads the counter back), after the orchestrating session took the PR over from a stopped
cloud session.

**Every game event counts every time, on its own site.** The page head loads GoatCounter's
`count.js` with `https://nappy.goatcounter.com/count` as its endpoint and page-load counting off, so
it carries only the game's events, and that site has sessions off: every event is an attempt. The
page visit stays on `josuakrause.goatcounter.com` as one request to its no-JS pixel, sending the same
path as before so the visit counts carry on. Neither runs on localhost, a private network, `file:`,
inside a frame, under WebDriver, or with `?debug=1`. `poster-torn`, `chat` and `checkpoint` lose
M208's once-per-attempt filter and are sent every time. `tools/goatcounter.py` reads the new site by
default, and its header says the counts are attempts, not visitors; events sent before this release
stay on the old site and need `--site` and that site's key.

**A key player is counted as one.** A run begun with a walking key or `space` sends
`nappy-controls-keys`; the touch controls still get tap aiming, since the controls mode is the
aiming origin they read and "by key" rides beside it.

**A torn poster that sends a patrol sends its own event**, `nappy-day-N-poster-pursuit`, beside
`poster-torn`, when the patrol is sent; a second tear while a patrol is on its way sends none.

**Choices made where the player was silent, open to overturn**: the pixel for the visit and
`count.js` for events, rather than the reverse or one script switching endpoints; every occurrence
of the three once-per-attempt events counted; "keys" meaning `space` or any walking key, as a flag
rather than a third controls mode; the pursuit counted when the patrol is sent, not when it reaches
the road; `tools/goatcounter.sh` also reading the main checkout's `.env` from a worktree.

Verified by the suites that cover the counter, the title's input, the posters and the event manager,
with the determinism check among them, and a live `tools/goatcounter.sh --check` against the new
site. Not yet seen in a real browser on the published page; that is the review item for the release.
