# minty-quail — The resistance suite is split by subject (minty-quail, tests-public-seams slice 3) · 2026-11-01

minty-quail's `tests-public-seams.md`, slice 3, the first half: `tests/test_resistance.gd` (about 6,150 lines, 109
test functions, one suite on one shard) is moved into subject suites, converting nothing. The split comes before the
rewrite onto public seams so that the rewrite can then run on the parts in parallel; the same result as splitting in
the rewriting pull request, ordered the other way, and open to overturn. The player folded the split into the
test refactor (tiny-lark #930, #931).

**Parity.** Every test function is called exactly once across the new files, in its original relative order, and no
test body changes. The runner's total for the suites matching `test_resistance` is 63,567 checks before and 63,567
after, and no failures.

The old suite's planned cost was 312 s; the heaviest part is now about 52 s. The costs come from one local run of the
eleven suites, scaled so they add up to the old row, since every other row in `tests/suite_costs.txt` is a CI average
on other hardware; `tools/ci-costs.sh` or `--record-costs` replaces them with measured ones.

**Where the cuts are.** The file's own section comments (the step table and touch, the director, re-placement,
alley avoidance, a finished task shown by the world, the placement kinds, the red arrow, the reachable targets
of M188) are the seams, with these changes: alley avoidance is two suites (where a mark and its guard stand;
a task riding on a look-alike and the handover traps), the finished-task section is merged into `steps`, day 9's
crossing tests leave the arrow section for their own suite, and the M188 reachability sweeps, which were nearly half
the file's run time, are four suites by test (a test is the smallest unit moved, so the single heaviest test,
`_test_a_mark_is_never_placed_in_an_alley_she_cannot_reach`, is a suite of its own).

**Shared helpers.** `tests/resistance_rig.gd` holds the city, the director builders, the walks and the sweeps more than
one suite uses, as `tests/ui_screens.gd` does for the pause suites; each part `extends` it, and the runner loads only
`test_*.gd`. A helper only one suite uses stays in that suite. `tests/run_tests.gd`'s per-suite line is 36 characters
wide, since a part's name is up to 34.

**Hidden state the move had to carry.** The suite's tests lean on what the tests before them left behind, and a part
that starts a process-clean run does not get it.
- `_test_a_perform_step_expires_when_its_rider_is_gone` and the tests after it in `steps` take the city standing, the
  last one a trap test had built; `steps` now builds the default city before them.
- `_test_every_mark_and_contact_stands_on_walkable_unobstructed_ground` reads the city the day-11 mast test last
  built (seed 1234567); `reach_contacts` builds that one before it.
- `RunFacts.completed_resistance_alley_tiles`, the alleys completed marks used, which the contact tests append to
  and nothing clears, held six tiles when `_test_every_guarded_target_sends_a_robber_from_off_screen` ran. Day 8's
  mark placement avoids them, so from an empty list the test finds a different start and checks 94 rather than 97
  times. `traps` sets those six tiles on entry. The rewrite onto public seams should remove the dependence instead
  of carrying it.

**Rejected.**
- Splitting only along the section comments: the M188 sweeps alone were about 45% of the file's run time, so one
  suite of them would have been the floor of the run instead.
- Duplicating the helpers into each part: eleven copies of one city builder, to be converted eleven times.
- Converting tests to public seams in the same pull request: the item's other half, a different kind of work.
