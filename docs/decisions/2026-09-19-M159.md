## Implementation and equivalence

`EventDef.look` derives the plain `has_a_spread` field whenever the look is assigned. The true
set remains ROADWORKS, BURNT_SHELL, STALL, ROADBLOCK, BARRICADE, CAFE, FALLEN_TREE, CAR_ACCIDENT,
BURST_MAIN, SCAFFOLDING and COLLAPSED_FRONTAGE. PROTEST and FIREFIGHT remain excluded and retain
their separate body-axis handling. `EventInstance.has_a_spread()` remains a compatible public
entry point returning the cached answer. Instance and manager body-axis selection, the
scheduler's ground-cache key and its corner filter read the cached field directly.

The classification audit finds one input, `look`. Production writes construct or deliberately
derive catalogue definitions; live phase transitions do not change that input. Resource copies
occur in several runtime paths, so definition immutability is not assumed. The eager setter
preserves mutation and shallow/deep duplication behavior. No geometry, event placement rule,
warning, halo, selection, collision, meter contribution, query cadence or gameplay tuning changes.
The [corner decision](2026-09-03-M64-a-corner-is-not-a-street.md), which keeps spread-drawn events
off corners, remains intact.

The author chooses a publicly writable derived field because a getter would retain a GDScript
call at every hot read. The look setter is the field's only production writer. This is a small
implementation choice, open to overturn; it is not a new player-authored rule. Tests protect the
derived value across defaults, every look and catalogue row, mutations in both directions,
shallow/deep duplication and independent copy mutation, unrelated geometry and phase changes,
and existing spread/corner/body consumers.

The danger test fixture sets its Camera2D callback to physics, matching the production scene and
removing the interpolation warning encountered during verification. Production camera behavior
does not change.

## Controlled measurements

The [measurement report](../evidence/m159-event-shape-cache-2026-09-29/README.md) retains commands,
exact revisions and collector hashes, compact per-run results, environment and acceptance checks.
The baseline is main at `41fd54a1cf5fee1a722dc7fcfb4cb30e95610b1e`; the implementation checkpoint is
`ea7147fff56eae004bcbe751130e1c35082d3c3b`. The supplemental series uses
`7e3b019e229de7c77c1fd2bc1cb000f43ffd9ba5`, whose production source, tests and collectors are
identical to the implementation checkpoint.

One measured process runs at a time on Apple M2/macOS with Godot 4.7.2, OpenGL Compatibility on
Metal, a 1280×720 viewport and 30 Hz physics. Seed 4242, day 1, arterial spawn and held north input
use identical five-second warmups and six-second active windows. All eighteen captures pass the
movement, population, drawing and collection acceptance checks: 200 walkers, 34 cars, median
51–52 live events, four visible events and approximately 549–552 px northward travel. Each capture
contains the same 175 existing remote-debug script-reload compiler warnings, apart from shifted
source line numbers; no runtime debugger errors are recorded.

Three baseline-first profiled pairs show main-loop wall medians of 15.071→11.609,
12.844→11.657 and 13.029→11.483 ms. The former classification callback's approximately 0.61 ms
median self attribution disappears, but that is not all CPU saved: profiling overhead disappears
with the call and work moves into its callers. Instance body-axis self time increases slightly
while its inclusive time falls. The compact results retain both measurements.

The three baseline-first profiler-disabled pairs reduce callback-interval medians by 0.538,
0.572 and 0.808 ms. Three supplemental cached-first pairs reduce them by 0.673, 0.691 and
0.762 ms. All six pairs show lower medians, approximately 4.9–7.3%, across both run orders.
These callback intervals are distinct from native engine main-loop markers. Tails remain mixed,
including a 29.730 ms maximum in one changed run, so the result does not establish uniformly
better tail latency or an absence of stutter.

Five alternating-order isolated trials compare 1,060,000 legacy matches with the same number
of cached reads over 53 definitions. Exact hit counts match in every pair. The operation takes
approximately 1.061–1.064 seconds versus 47.2–47.8 ms, a 95.5% reduction in this deliberately
dense isolated workload. That reduction is not a predicted frame gain. Native host measurements
establish no phone, browser, GPU, memory-residency or perceived-smoothness improvement.
