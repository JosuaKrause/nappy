# minty-quail — The save suite drives public seams, and `test_run_checkpoints.gd` loses five private reads · 2026-11-01

minty-quail's `tests-public-seams.md`, slice 5: `tests/test_save.gd`. The player allows the item in slices alongside the
other steps "as long as the final result is the same" (inbox #813 in curly-moose). The item's rule for a seam is that
the game itself can use it: a public member only a test reads is not a seam, however it is named.

**Counts, before -> after.** Private reads are the lines `rg -v '^\s*#' <file> | rg -o '\._[a-z]\w*'` finds; direct
frame calls are `rg -v '^\s*#' <file> | rg -c '\._(physics_)?process\(|process_frame\.emit'`.

| Suite | Private reads | Direct frame calls |
|---|---|---|
| `test_save.gd` | 320 -> 0 | 0 -> 0 |
| `test_save_wiring.gd` (new; the checks of `test_save.gd` that build a script-only `main`) | 0 -> 84 | 0 -> 0 |
| `test_run_checkpoints.gd` | 129 -> 124 (its five calls of the private save functions) | 14 -> 14 |

The 84 reads in `test_save_wiring.gd` are the 13 tests that reach `main`'s members (`_summary`, `_title`, `_flow`,
`_resume`, `_on_title_start()`, `_write_dawn_for_a_resumed_run()`, `_save_now()`, `_save_indicator` and the rest) and the
three checks of what `main._save_now()` adds to a write. Nothing was dropped to get `test_save.gd` to zero: the 13 tests
moved whole, with their private reads, and the file gained its own header saying why. What stops them being converted is
cost, not a missing seam: the `test_main` slice reached the title, the resume gate and the continue button by booting a
real `main` and driving it with real input and real frames, and added only `Main.use_reload()` and `Main.use_quit()`. The
file is converted the same way, which is part of the item's remaining work and named there; it is not handed to a slice
that does not do it.

**Built.**
- `RunConfig.headless` (the display server is the null one) is a field of the configuration, read once by `at_boot()`
  and given to `parse()` as `headless_display`, true by default, so every existing caller and every test's
  configuration is a headless run as before. `GameSave.uses_save()` reads `config.headless` where it asked
  `DisplayServer.get_name()`. A test that wants the saving of a windowed run hands `GameSave.configure()` a config
  parsed with `headless_display` false; its `write()`, `try_resume()` and `clear()`, the three calls the game makes,
  then reach the scratch file `set_path_override()` names. `GameSave` no longer reads the display server; `Telemetry`,
  `FrameTrace`, `FrameRecorder`, `RigLock` and `AutoScreenshot` still do.
- `GameSave.Flushes` is the table of web flushes waiting for the browser, taken out of `GameSave`'s statics:
  `register()`, `answer()` (the page's callback), `fail()` (the deferred failure when the page is unreachable),
  `advance()` (one frame's time, clamped to `MAX_FLUSH_STEP_SECONDS`, never negative), `waits_for()` and
  `is_empty()`. `GameSave` holds the one instance the game uses and passes it to the page and to the frame clock; a
  desktop run or a test builds its own and gives it the page's answer or the frames' time, with no browser and no
  static to put back.
- `GameSave.moment_result()` is public: it is the pure half of `write()` and `clear()`.
- `SaveIndicator._init(timeline)` takes the symbol's `Showing` timeline, a fresh one by default, so whoever builds the
  symbol keeps a hand on the object it begins, answers and ages. `SaveIndicator.use_home(node)` parks symbols that outlive
  their scene at a node instead of the tree's root; it is the old `_home_override` static under a public name, not an
  injected dependency (see Left). `outlive_the_scene()` now does nothing for an idle symbol (it was
  `main._carry_the_save_symbol_over()`'s own test), so `main` calls it unconditionally and the rule sits with the owner.

**Rejected.**
- Public `_write_now()`, `_read_now()` and `_clear_now()`: they bypass the gate the game never bypasses, and a test that
  uses them tests a path no run takes. Their callers in the suite go through `write()`, `try_resume()` and `clear()`.
- Removing `GameSave._uses_save_override` in this slice: `test_finale` and `test_move_poses` boot a real `main` under a
  debug flag (`--invincible`, `--no-save`), and the debug policy keeps a flagged run off the save however windowed its
  configuration is, so they still need it. `main` hands `configure()` the configuration the suite gave it, so a suite
  whose configuration is windowed and flagless needs no override: `test_park_return` passes one now and drops it.
- Keeping `_write_now()`'s own refusal of an ended run: `write()` is the one path to `_write_now()` in `src/` and
  refuses an ended run first, so the second check was a branch no test or run reaches. It is removed, and the ended-run
  test goes through `write()`.

**Left, not converted.** `SaveIndicator.use_home()` renames a static only tests call; `SaveIndicator.carried()` is
static, so the home cannot be handed to a symbol. It is process-wide state the runner resets, listed in the item for
the hidden-statics work. `test_save_wiring.gd` is not converted (above).

**Parity: old check -> new check.** `test_save.gd` keeps its tests, their order and their doc comments apart from the 13 that moved; a row
says what changed in how a fact is read.

`test_save_wiring.gd` holds the 13 tests that moved whole and the three `main` halves above: the two focus-loss checks, the five dawn and gate checks, the
three title-to-brief or ending checks, the day-14 hand-over, and the two orderings read off `main.gd`'s source. They
use `GameSave.configure()` with a windowed config, `write()`, `try_resume()` and `clear()` in place of
`_uses_save_override` and the private functions.

Two order dependencies the old file had are gone: `test_save.gd` now connects `GameSave.clear_when_a_run_ends()` itself
(it held only when an earlier suite had booted a `main`, and a run of the suite alone failed three checks), and the
test that ends a run puts the ending back.
