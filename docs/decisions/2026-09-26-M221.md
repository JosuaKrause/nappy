# M221 — A failed day leaves no chalk mark behind · built 2026-09-27

*([PLAYTEST-143](../playtests/PLAYTEST-143.md), statement 7: "chalk marks don't get properly reset
on failed days accumulating more and more chalk marks in the same alley")*

**The cause.** Touching a mark whose next step is guarded calls `_begin_step()` twice in one
completion: the second overwrote `_contact`, leaving the touched mark standing for good, and
`_maybe_set_a_trap()` overwrote `_guard`, leaving the mark's own robber alive. Failed days only made
the pile visible.

**Built (PR #414).** `_begin_step()` frees the old contact and `_maybe_set_a_trap()` retires the old
guard before placing new ones. A test checks both are freed after a completed mark.
