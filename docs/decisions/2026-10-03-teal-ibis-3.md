# teal-ibis — The trailer checks its disk headroom · built 2026-10-04

*([snowy-newt](../playtests/2026-10-03-snowy-newt.md): measure what accumulates and add safeguards
so the drive does not fill; the preflight itself and its warn-or-refuse rule are
[teal-ibis-2](2026-10-03-teal-ibis-2.md))*

**Built (PR #520).** `tools/trailer.sh` runs the same disk preflight as the other capture tools
(`tools/lib_disk_headroom.sh`): before its first render it charges `record-second` for the summed
seconds of the shots asked for against the frame directory under `$TMPDIR`, and before its atlas
repair it charges an `import` against the project's `.godot`. Below the reserve it warns and
carries on; it refuses only when the batch cannot fit, with the hint to render fewer shots
(`--shot NAME` renders one). `--list` and `--validate` write no frames and ask for no space.
`tools/test_disk_headroom.py` holds the trailer's refusal, its warning band, and that the listing
modes never ask; the using-tools row for the trailer names the check.

**Proposed, not asked for, and open to overturn:** each shot is charged its render seconds (the
longer of its in-point plus length and its recipe's playback), summed and rounded up, which is an
upper bound, since a shot's frames are deleted before the next renders and the real peak is the
largest shot; `--check` charges the same sum; the import check sits inside the atlas repair, so it
runs only when pages are stale, and no test reaches it.

**Verified.** `tools/test_disk_headroom.py`, `tools/test_cli_help.py`, `tools/pycheck.sh`,
`tools/lint.sh` and `tools/check.sh`, with the trailer's engine stubbed; no real trailer was
rendered.
