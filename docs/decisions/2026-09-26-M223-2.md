# M223 — The queue's order is a priority band in each entry · 2026-09-26

*([2026-09-26-brisk-heron](../playtests/2026-09-26-brisk-heron.md), statements 13–14: "what's the
point of any of this if there is still a centralized TODO.md ordering list? can we think of a better
solution there? a priority system?" · "1 sounds good with. only change I would do is for "now" do
reverse chronological maybe?"; then, shown the result: "let's move M226 and M227 to now".)*

**Why.** M223 split the queue into a folder per entry so that two PRs stop colliding in one file,
but `docs/TODO.md` kept an order list that every PR adding or closing an entry edited. Three ways
were offered — a band in each entry with a command that prints the order, the list kept but edited
only at a session's end, or dependency links alone — and the player took the first.

**What is built.** Each entry's `README.md` opens with `priority: now|next|later|parked` and, where
the entry truly waits on another, `after: <entry folder name>` lines. `tools/queue.sh` prints the
queue: bands in that order, `now` newest first and the others oldest first by the folder's date,
same-day entries by name, and never an entry before an open entry it waits on. An `after:` naming a
closed entry (no folder, a record under `docs/decisions/`) holds nothing back and prints as
`(after X, closed)` for session-cleanup to delete, so the PR that closes an entry never edits the
entries waiting on it (a reviewer's proposal the orchestrator took, open to overturn). `docs/TODO.md` keeps its header and says to run the command. The lint runs
`queue.sh --check` and rejects a missing band, a band outside the four, a band line outside the
opening block, an `after:` naming nothing, and a cycle. `tools/new-name.sh todo` writes
`priority: later` unless `--priority` says otherwise.

**The mapping from the old list**, the implementer's and open to overturn: what the list put first
went to `now`, the numbered gameplay queue to `next`, the unordered tail to `later`, and nothing to
`parked`; M109 (SVG to PNG) to `next` as the track beside the gameplay queue; `after:` only where an
entry's own text names a wait (M56 on M99 and M100, M213 on M137, M129 and M228 on M223). M125,
item 0 of the old list, prints last in `next`, because oldest-first puts the newest there. The
player then moved M226 and M227 to `now`. Newest-first within `now` was said with a "maybe" and is
shown in the command's output.

**Removed from `TODO.md` with the list**: the "Bind prepared environment art" table, now a paragraph
in M100's entry, and paragraphs that were history or repeated records and review items. The one live
rule among them, "nothing merges carrying a defect that was already found", is in the pr-review
skill, citing M90.

**Not changed**: `tools/convert-queue-edits.py` and `tools/migrate-queue.py` still expect the old
order section; no open PR is on the old format, and an entry one of them wrote without a band line
would be stopped by the lint.
